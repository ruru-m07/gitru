## Accepted scope and invariant

Add direct manual GitLab.com PAT connection and membership repository discovery
through the existing native account/vault/epoch/journal/scheduler/query model.
Desktop accounts remain independent of Gitru cloud. This is the first concrete
second-provider slice, not a promise of GitLab MRs/issues/todos or self-hosted
support. R111/R127/R128/R109 retain those distinct features/trust assessments.
Only Repositories is Supported; every resource detail/inbox/write facet is
explicitly Unsupported. No new database schema or migration is expected. Preserve
R79 narrow notification access, R98 leases, R96 immutable authored links and R95
owned crash-safe credential promotion.

Use a fixed `collaboration_connect_gitlab(token)` command, main-only like GitHub
credential mutations, normally generated by `make typegen`; expose the direct
`collaboration.connectGitlab(token)` SDK entry point. Renderers supply neither
installation URLs nor arbitrary API routes/native token locations. No CLI import
or OAuth/broker/relay is introduced. Tokens remain opaque native SecretToken
values and OS-vault references; no token is persisted in SQLite, renderer stores,
errors or logs. No personal configuration/credentials/vault/live account may be
inspected for unattended qualification.

## Repository adapter and transport

Implement a GitlabProvider with explicit FACETS declarations. Do not use
ProviderProfile::read_only unchanged: it currently includes PRs/issues. Inbox
semantics None, notifications_supported false, no implicit future-feature grant.
Use member projects, not the personal-namespace-only `/users/:id/projects`.
Initial endpoint:
`/api/v4/projects?membership=true&pagination=keyset&order_by=id&sort=asc&per_page=50`.
Normalize native project ID and complete path_with_namespace without splitting
owner/name; nested groups, Unicode presentation, null optional values and rename
are ordinary provider-neutral data. Immutable identities/local selection survive
renames; old/new conflicting path aliases remain conservative. Reuse shared
resumable page checkpoints and existing two-complete-traversal absence policy;
partial/error/capped traversals never retire unseen rows.

Follow only validated server next Link: exact HTTPS origin, `/api/v4/projects`,
fixed membership/keyset/order/sort/per_page filters, bounded canonical id_after
and no unexpected/duplicate auth/sudo/query filters, userinfo or fragments.
Respect actual server continuation rather than synthesizing new pages or using
missing totals as proof. A response with malformed continuation is an error and
cannot claim completion. Preserve reset/cancellation/authorization/run fences.

GithubHttp includes GitHub-only version/Accept/scope/throttle assumptions. Add a
small GitLab transport or extract only proven common low-level safety, retaining
all existing GitHub regressions. Sensitive PRIVATE-TOKEN header, pooled bounded
GETs, fixed API origin/path, bounded body/time/redirects and credential redaction
are mandatory. No request may forward a token to a foreign host or operation.
401 => authentication,403 => permission,429 => quota/backoff; honor valid
Retry-After and observed reset metadata with safe bounded fallback if omitted.
Persist strict provider:rest/retry barriers through the common scheduler. Never
hardcode advertised tier quotas or reset a cooldown through manual refresh.

## Review corrections and approved probe-failure seam — before source edits

Root and independent peer review find two backoff gaps with executed synthetic
transport reds: long valid Retry-After172800 was truncated to86400, and explicit
Retry-After on503/redirect was discarded/followed immediately. GitLab transport
now preserves representable server waits (safe saturation for numeric overflow),
keeps503 Unavailable while retaining delay, and returns bounded delayed-redirect
intent without sleeping a worker or forwarding credentials. The native lifecycle
review also finds a source-derived crash gap: a successful final probe's quota
was persisted after credential cutover. The corrected transaction writes the
maximum existing/observed provider barrier atomically with promotion; new
kill/rollback tests qualify it, without claiming an executed original red.
[RFC9110 Retry-After](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.2.3)
is the primary HTTP semantics reference.

A further independent review establishes partial-probe barrier loss: /user proves
immutable actor, then /projects fails with observed cooldown. Plain ProviderError
loses that actor, so a previously connected SAME exact actor can continue using
its old grant without the new barrier. Root approves a narrow native-only
connection-probe outcome/failure carrying optional proven immutable actor ID plus
the existing typed redacted ProviderError. Default providers retain old probe
semantics; GitLab publishes proven actor evidence only after authorized /user
identity validation. Runtime may match only an existing exact provider+installation
+immutable actor under the lifecycle lock, persist its maximum same-epoch quota,
and return the original validation error without replacing its token, advancing
epoch, clearing caches/drafts or creating a new account. An unverified actor
never poisons guessed/current/other-provider accounts. No migration/wire DTO
change is expected. Independent actual two-response synthetic probes must prove
oldgrant/draft preservation, strict restart barrier and zero dispatch before
expiry, plus unknown/mismatched actor controls. The direct low-level probe API
may remain a compatibility wrapper; keep lifecycle helper behavior explicit.


The partial-probe seam also requires a native quota-only writer transaction.
Existing persist_rate_limit reads its previous deadline outside the writer, so
concurrent same-epoch observations can overwrite a later deadline with a shorter
one. Root approves Store.merge_provider_budget and a shared internal cutover
helper that compares maximum deadlines under the single writer transaction,
rechecks exact current epoch, preserves last-success evidence and publishes a
quota revision only. Known AuthRequired/Disconnected actors may retain observed
quota without reactivating grants; old-epoch late observations cannot commit.
The ordinary epoch accessor requires Active, so inactive behavior needs this
explicit quota-only guard, not an assumed set_sync_status exception. Add
independent concurrent/max/old-epoch/inactive proof. A picked worker delayed by
the connection lifecycle must recheck strict provider backoff after acquiring
its gate and before credentials/HTTP, rather than relying on an earlier pick.
